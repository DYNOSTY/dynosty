# 게임 계산과 3D 화면이 주고받는 정보

이 문서는 SETUP-007의 연결 규격입니다. 공용 형식은 `packages/game-core/src/scene.ts`에 있으며 React, Babylon.js, DB, 브라우저 객체를 포함하지 않습니다. 주민 수·식량·이동 속도 같은 게임 규칙과 실제 모델은 아직 정하지 않습니다.

## 전달 단위

`SceneSnapshot`은 표시할 객체의 **전체 목록**입니다. `schemaVersion`은 현재 `1`이며 게임 저장 상태의 버전과 별개입니다. 이 예제는 기존 `GameState`나 API의 초기 상태 응답을 바꾸지 않습니다. 호환되지 않는 변경을 할 때는 표시 정보 버전과 양쪽 코드를 함께 변경합니다.

| 항목                 | 뜻                                                                       |
| -------------------- | ------------------------------------------------------------------------ |
| `schemaVersion`      | 표시 정보 형식의 버전, 현재 `1`                                          |
| `entities`           | 이번에 표시할 주민과 건물의 전체 목록                                    |
| `id`                 | 객체를 구분하는 비어 있지 않은 문자열. 주민·건물 전체에서 중복 없이 유지 |
| `kind`               | `resident`는 주민, `building`은 건물                                     |
| `position`           | `{ x, y, z }` 숫자 좌표. 오른쪽·위쪽·앞쪽 기준이며 모델의 바닥 중심 위치 |
| `headingRadians`     | 위쪽 축을 중심으로 한 회전 각도. 단위는 라디안                           |
| `visible`            | `true`면 표시, `false`면 객체를 유지하면서 숨김                          |
| 주민의 `motion`      | `idle`은 대기, `walking`은 걷기 표시 요청                                |
| 건물의 `highlighted` | 강조 표시 요청 여부. 건설 완료나 생산 상태를 뜻하지 않음                 |

위치와 방향에는 유한한 숫자만 사용합니다. 좌표 한 단위의 실제 길이는 기획·3D 작업에서 정하며, 현재 예제 크기를 실제 게임의 길이나 비율로 해석하지 않습니다. 공용 정보에 Mesh, Vector3, 함수, HTML 요소를 넣지 않습니다. Worker가 사용하는 값 복사 방식으로 전달할 수 있는 일반 객체만 사용합니다.

같은 `id`의 정보가 다시 오면 기존 객체의 위치·방향·표시 상태를 갱신합니다. 목록에서 사라진 객체는 삭제하고 모델과 재질을 정리합니다. 같은 `id`의 종류가 바뀌면 기존 객체를 정리한 뒤 새로 만듭니다. 빈 목록은 모든 표시 객체를 지웁니다. 버전 오류·중복 식별값·비정상 좌표는 장면을 바꾸기 전에 거부합니다.

## 전달 경로와 예제

1. Core의 `createSceneExample()`이 표시 정보만 만듭니다.
2. Worker는 시작할 때 `{ type: "scene", snapshot }` 메시지를 보냅니다.
3. React 화면은 받은 정보를 보관하고 3D 장면 준비가 끝나면 적용합니다. 먼저 도착한 정보도 장면 준비 후 적용합니다.
4. `scene-entities.ts`가 식별값으로 Babylon 객체를 찾거나 만들고 정보를 반영합니다. 화면 종료 시 Worker, 표시 객체, 장면과 렌더링 엔진을 정리합니다.
5. **3D 연결 예제 바꾸기**를 누르면 `{ type: "toggle-scene-example" }` 명령이 Worker로 전달됩니다. Worker가 다른 표시 정보를 보내며 주민 위치가 바뀌고 건물이 강조됩니다. 다시 누르면 처음 표시로 돌아옵니다.

```ts
const message: GameWorkerMessage = {
  type: "scene",
  snapshot: createSceneExample(),
};
// 예제 주민: example-resident-1, 위치 (-2, 0, 1), 대기
// 전환 후: 같은 식별값, 위치 (2, 0, 1), 걷기 표시 요청
```

현재 모델은 종류별 상자입니다. `walking`은 색상으로만 구분하며 실제 이동 계산이나 걷기 애니메이션을 구현하지 않습니다. 박찬님의 모델을 연결할 때는 공용 정보를 유지하고 `scene-entities.ts`에서 모델 생성과 애니메이션 적용을 교체합니다. 실제 공룡 모델과 애니메이션 작업은 3D 카드에서 진행합니다.

## 확인 방법

저장소 지정 Node와 pnpm을 사용해 `pnpm check`를 실행합니다. 공용 형식의 값 복사·식별값·좌표 검사와 Babylon 객체의 재사용·갱신·숨김·삭제·종료 정리를 확인합니다. 객체 검사는 브라우저 그래픽을 사용하지 않는 Babylon 검사 엔진으로 수행합니다.

로컬 DB를 켠 뒤 `pnpm test:e2e`를 실행합니다. 실제 브라우저에서 예제 전환·원상 복귀·새로고침을 확인하고, 전환 시 캔버스 이미지가 달라지며 게임 날짜가 변하지 않는지 검사합니다. 기존 API·DB 연결과 하루 진행 검사도 함께 실행합니다. 이는 연결 검증이며 실제 공룡의 외형·애니메이션·게임 성능을 검증하지 않습니다.
