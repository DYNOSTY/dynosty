## 다음 작업 순서

1. **기획 확인 묶음:** U01과 C01~C06을 먼저 확인한다. 석탄 포함 여부(C04), 연료 전환 범위(C05), 시간·추방·단서 순서(C01~03·06)를 승인 없이 기본값으로 정하지 않는다.
2. **PLAN-002:** 석탄을 포함한 자원 목록·이름·단위·식별값을 확정한다. 자원 목록이 정해지면 초기 재고 표를 만들 수 있다.
3. **PLAN-003 / PLAN-004:** 확정 자원에 맞춘 초기 주민·재고 표와, 단계별 시간·사건 순서를 각각 정리한다. 두 표는 병행 준비할 수 있으나 서로 의존하는 값은 함께 대조한다.
4. **PLAN-005:** 공통 실패·단계별 예외·3개 엔딩의 조건과 우선순위를 확정한다. 특히 4단계 타이머와 5단계 10일 평가, C04·연구 해금 순서와 맞춰 확인한다.
5. **PLAN-006:** 승인된 값과 규칙만 하나의 데이터 파일과 검증 조건으로 정리한다. H의 100 고정 검증 예제도 확정된 추방 규칙에 맞춰 설계하며, 문서에 있는 Python 예제를 그대로 실행·도입하지 않는다.
6. **CORE-001 → CORE-002 → CORE-003 → CORE-004:** 초기 상태, 시간, 식량 소비, 부족 경고 순으로 구현한다. 그 전에는 현재 연결 예제를 실제 주민·경제 계산으로 확대하지 않는다.

3D 작업은 이미 완료된 SETUP-007 규격을 기준으로 3D-001부터 별도로 준비할 수 있다. 다만 마을 실제 크기·정원·모델 종류와 비율은 기획/3D 확인이 필요한 범위로 구분한다.

## 완료 범위와 보류 범위

- 완료: 두 최신 마스터의 출처·버전·수정 시각 확인, 전체 본문 비교, 차이 6개와 미확정 13개 분류, 확인 담당 역할·후속 순서 정리.
- 보류: 어느 규칙을 채택할지에 대한 기획 승인, 게임 데이터 확정, 실제 게임 규칙 구현.
- 원본 Drive 문서와 게임 코드는 변경하지 않았다. 이 로컬 검토 문서는 커밋·푸시하지 않았다.
- 프로젝트 코드 검사가 기획 판단의 정답을 증명하지 않으므로 전체 빌드·브라우저 검사를 반복하지 않았다. 문서 내 숫자는 별도 산술 대조를 수행했다.
