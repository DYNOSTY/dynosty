# 역할과 연결

개발자 두 명이 한 저장소에서 협업하고, 프로그램은 역할별로 분리합니다.

| 영역      | 담당                     | 경계                               |
| --------- | ------------------------ | ---------------------------------- |
| Web       | 화면 개발 담당           | 3D·화면·입력, Worker 실행          |
| Game Core | 게임 로직·서버 개발 담당 | 게임 상태와 순수 계산              |
| API       | 게임 로직·서버 개발 담당 | HTTP 요청·계정·온라인 저장·DB 접근 |
| Infra     | 게임 로직·서버 개발 담당 | 실행 환경·배포·백업·복구           |
| 게임 설계 | 기획·디자인 담당         | 규칙·미션·시각 디자인 결정         |

```text
Web ── 명령 ──→ Worker 안의 Core ── 상태 ──→ Web
Web ── HTTP ──→ API ── SQL ──→ PostgreSQL
                 └─ Core의 공용 상태 형식 사용
```

현재 API는 공용 코어의 초기 상태를 반환합니다. Worker는 별도로 초기화되어 날짜를 진행합니다.
이는 두 실행 경로의 연결 확인용이며, API와 Worker 상태의 저장·동기화 기능은 아직 없습니다.

Core의 패키지 이름은 `@dynosty/game-core`입니다. Web과 API는 워크스페이스 안에서 이 패키지를 사용합니다.
개발 시작 시 Core를 먼저 빌드하고, 이후 변경은 감시 모드로 다시 빌드합니다.
Web은 바뀐 코드를 반영하고, API도 Core 출력 변경을 감시해 재시작합니다.

Web의 개발 서버는 `/api` 요청을 로컬 API로 전달합니다. 브라우저가 DB에 직접 접속하지 않습니다.
운영 환경에서는 별도로 정한 HTTPS 주소와 라우팅을 사용해야 합니다.
