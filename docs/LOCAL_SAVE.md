# 예제의 로컬 저장과 불러오기

화면의 **예제 저장**, **저장 불러오기**, **이전 저장 불러오기** 버튼을 사용합니다. 저장 대상은 현재 예제의 날짜와 3D 예제 표시 모드(대기/걷기)뿐입니다. 주민·재고·시간 배율·미션 등 미확정 게임 규칙은 추가하지 않습니다.

## 저장되는 정보

공용 규격과 값 검사는 `packages/game-core/src/save.ts`에서 관리합니다. 이 코드는 React·Babylon.js·브라우저·DB에 의존하지 않습니다.

| 항목                  | 뜻                                                                       |
| --------------------- | ------------------------------------------------------------------------ |
| `format`              | `dynosty-example`: 현재 연결 예제의 저장임을 구분                        |
| `saveVersion`         | 저장 형식 버전, 현재 `1`                                                 |
| `game`                | `{ schemaVersion: 1, day }`, 날짜는 1 이상의 안전한 정수                 |
| `sceneExampleUpdated` | 3D 연결 예제의 전환 여부. 기존 예제 생성 함수를 통해 위치·표시 상태 복원 |

3D 엔진 객체나 모델 파일은 저장하지 않습니다. 표시 규격의 전체 객체를 임의로 저장·편집하는 기능도 아닙니다. 실제 게임 상태와 에셋이 추가되면 저장 버전과 이전 데이터 변환 정책을 별도로 설계해야 합니다. 현재는 지원하지 않는 버전을 자동 변환하지 않고 거부합니다.

## 최근 저장과 직전 저장 보존

브라우저의 `localStorage`에서 `dynosty.example.saves` 키 하나를 사용합니다. 저장 묶음의 버전은 `storageVersion: 1`이고, `current`는 최근 저장, `previous`는 직전 저장입니다.

1. 저장 버튼은 Worker에 현재 상태를 요청합니다. 화면에 뒤늦게 표시된 값을 대신 저장하지 않습니다.
2. 새 데이터와 기존 두 기록의 형식을 먼저 검사합니다.
3. 새 상태를 최근 저장으로, 기존 최근 저장을 직전 저장으로 묶습니다.
4. 묶음 전체를 `setItem` 한 번으로 기록합니다. 두 키에 나누어 쓰지 않으므로 용량 부족 등으로 쓰기가 실패하면 기존 두 기록이 유지됩니다.

보관 범위는 **최근 두 번의 성공한 저장**입니다. 세 번째 저장에 성공하면 가장 오래된 기록은 교체됩니다. 쓰기에 실패한 상태는 저장 완료라고 표시하지 않으며 현재 실행 중인 예제도 바꾸지 않습니다.

## 잘못된 저장 처리

- JSON 손상, 다른 형식, 미지원 버전, 잘못된 날짜·표시 모드를 거부하고 안내합니다.
- 검사를 통과한 상태만 Worker가 다시 확인한 뒤 적용합니다. 불러온 뒤의 하루 진행과 예제 전환도 복원된 상태에서 이어집니다.
- 최근 저장이 손상되어도 묶음 형식과 직전 저장이 유효하면 **이전 저장 불러오기**로 실행 상태를 복원할 수 있습니다.
- 손상된 기록은 새 저장으로 자동 덮어쓰거나 삭제하지 않습니다. 직전 저장을 불러와도 손상된 원본을 고치지 않습니다. 원본이 손상된 상태에서는 새 저장과 파일 가져오기도 거부합니다. 유효한 직전 저장은 파일로 내보낼 수 있지만 손상 기록 정리 기능은 아직 제공하지 않습니다.
- 저장 권한이나 용량 문제는 원본 오류 내용 대신 안전한 안내 문구로 표시합니다. 같은 저장을 자동 재시도하지 않습니다.
- 페이지 시작·새로고침·불러오기는 저장 내용을 쓰거나 지우지 않습니다. 새로고침 후 예제는 처음 상태로 시작하며, 버튼으로 저장을 불러옵니다.
- 저장 요청 중에는 저장·불러오기·예제 조작을 잠시 막고, 요청 번호가 일치하는 응답만 처리합니다.

로컬 저장은 현재 브라우저의 같은 사이트 주소에 남습니다. 다른 브라우저·주소에서는 자동 공유되지 않으며 사이트 데이터를 지우면 없어집니다. 아래 파일 내보내기로 별도 백업을 만들 수 있습니다. 계정·클라우드 동기화는 제공하지 않습니다.

## 저장 파일 내보내기·가져오기

**최근 저장 내보내기** 또는 **이전 저장 내보내기**로 해당 기록을 JSON 파일로 다운로드합니다. 실행 중인 미저장 상태를 자동으로 저장하지 않으므로 현재 진행을 백업하려면 먼저 **예제 저장**을 누릅니다. 다운로드 요청 자체는 기존 기록이나 실행 상태를 바꾸지 않습니다.

파일에는 위의 `ExampleSave` 형식(종류·저장 버전·날짜·3D 표시 모드)만 포함합니다. 로컬 저장 묶음 전체, 설정, 음원·영상 파일은 포함하지 않습니다. 파일명은 `dynosty-example-day-날짜-current.json` 또는 `previous.json` 형식입니다. 브라우저가 실제 파일 저장을 담당하며 화면에서는 다운로드 요청까지 안내합니다.

가져오기는 다음 순서입니다.

1. **가져올 저장 파일**에서 JSON을 선택합니다. 이름·빈 파일 여부·크기를 내용 읽기 전에 검사합니다. 한도는 64KiB(65,536바이트)이며 현재 작은 예제 저장을 위한 제한입니다.
2. JSON 구문과 공용 버전·날짜·표시 모드를 검사하고 미리보기를 표시합니다. UTF-8 BOM이 있는 JSON도 읽습니다. 이 단계는 기존 저장을 쓰지 않습니다.
3. **파일 가져오기**를 누르면 가져온 기록을 최근 저장으로, 기존 최근 저장을 직전 저장으로 묶어 단일 쓰기로 보관합니다. 보관 범위는 여전히 최근 두 기록이며 더 오래된 직전 기록은 성공한 가져오기로 교체됩니다.
4. 실행 중인 예제는 그대로 유지합니다. **저장 불러오기**를 눌러 가져온 상태를 Worker와 화면에 적용합니다.

잘못된 확장자·크기·내용·미지원 버전·파일 읽기 실패는 확정 전에 거부합니다. 쓰기 실패 시 기존 최근·직전 기록의 원문이 유지됩니다. 기존 로컬 기록이 손상된 경우에도 자동으로 덮어쓰지 않습니다. 저장 공간 부족·읽기 권한 문제를 자동 재시도하지 않으며 내보내기·가져오기에 네트워크 전송은 없습니다.

파일 검사는 비동기 요청 번호로 이전 응답과 화면 종료 후 응답을 무시합니다. 확정 성공 후 버튼을 비활성화해 같은 선택을 중복으로 반영하지 않습니다. 다운로드 Object URL은 요청 후 지연 해제하며 화면 종료 시 남은 참조와 타이머를 정리합니다.

## 검증 범위

`pnpm check`로 공용 저장 데이터 검사와 저장 보존 검사를 실행합니다. 로컬 DB를 켠 뒤 `pnpm test:e2e`로 실제 브라우저의 저장·복원·새로고침, 손상 데이터 거부, 실패 후 기존 기록 보존을 확인합니다.

용량 부족 검사는 브라우저 쓰기 단계에 `QuotaExceededError`를 주입합니다. 저장 공간을 실제로 가득 채우거나 디스크 장애를 발생시키는 검사는 아닙니다. 여러 탭의 동시 저장 충돌 조정과 브라우저 외부에서 삭제된 데이터의 복구는 검증 범위가 아닙니다.
