# 마른 목재20 조달 체험판

상단 **마른 목재20 조달 체험하기**로 들어갑니다. 기존 이야기의 정찰대 사건 이전, 비가 새는 둥지에 필요한 자재를 조달하는 구간입니다. 본편5단계·정책24개를 완성한 체험이 아닙니다. 기존 시나리오·영상·음성·생존 예제의 재고와 저장을 유지합니다.

## 한 번 끝까지 플레이하기

1. 공급 제안A/B의 철재 비용·도착 시각·품질·보완 일손을 비교합니다. 선택만으로 예약이나 지불은 생기지 않습니다.
2. 약정을 확정하면 철재와 운송·검사 일손1명을 예약합니다. 출발 전 취소는 예약만 해제합니다. 출발 때 철재를 지불하며, 출발 후 창을 닫아도 환급하지 않습니다.
3. 시간을 시작하거나 **다음 작업 완료까지**를 누릅니다. 수레가 이동하며 도착해도 사용 가능 재고는0입니다.
4. 전량 품질 검사와 수량·손상·수령 확인을2시간 진행합니다. A는 정상16·격리4, B는 정상20입니다. 정상분 수령 버튼으로 받아야 배분할 수 있습니다.
5. A는 정상16을 먼저 배분할 수 있습니다. 일손2명을 배정해 젖은4를4시간 건조·재검사합니다. 그 전에는 격리분을 사용하지 못합니다.
6. 마른 목재20을 둥지에 배분한 뒤 **지붕 보수·사용 확인**을 누릅니다. 지붕의 보완 표시와 주민 위치가 바뀌며 기한·남은 철재·보완 일손의 차이를 보여줍니다.

두 제안 모두 지연 없이 진행하면12시간 정각 완료입니다. A는 철재4, B는 철재2가 남습니다. 품질은 고정 예시이며 재시작·불러오기 때 몰래 바뀌지 않습니다. 다음 작업 완료 명령도 도착·검사·보완 경계를 건너뛰지 않습니다. 결정 지점에서는 일시정지합니다.

기한을 넘기면 임시 쉼터를 표시하고 계속 보완·배분해 마칠 수 있습니다. 즉시 사망·추방으로 끝내지 않습니다. **처음부터 다른 선택**은 확인 후 체험만 새로 시작하며 저장 기록을 지우지 않습니다. **생존 예제로 돌아가기**는 체험 시간을 멈추고 기존 화면으로 돌아갑니다. 다시 들어오면 같은 체험을 이어봅니다.

## 저장과 정리

**체험 저장·체험 불러오기·이전 체험 불러오기**는 `dynosty.timber.saves`에 최근/직전 두 기록을 원자적으로 보관합니다. 파일 형식은 `dynosty-timber`/저장버전1입니다. 기존 생존·연결 예제 저장 키와 분리해 기존 형식 마이그레이션이 필요하지 않습니다.

물품 상태·철재 예약·일손·출발/작업 완료 시각·처리ID·이력을 검사합니다. 손상·미지원 버전·저장 쓰기 실패는 원본을 덮어쓰지 않습니다. 불러오기는 일시정지 상태이며 종료·탭 밖 시간을 더하지 않습니다. 같은 명령의 재전송과 잘못된 순서의 재수령·배분·사용은 재고를 중복 증가시키지 않습니다. 체험 파일 내보내기·클라우드 저장은 이번 범위가 아닙니다.

독립 Worker가 Core 계산을 실행하고 UI에는 결과만 전달합니다. 화면·저장 명령은 `timber-protocol.ts`, 계산·검증은 `packages/game-core/src/timber.ts`, 저장은 `timber-save.ts`, 장면 표시는 `timber-scene.ts`입니다. 기존 영상/오디오 모듈과 이벤트 재생 조건을 바꾸지 않았습니다.
