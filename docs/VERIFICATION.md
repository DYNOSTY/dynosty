브라우저 검사는 Linux Chromium의 소프트웨어 그래픽으로 실행했습니다.
실제 사용자 PC의 GPU·모바일·다른 브라우저와 56명 주민·날씨·건물을 함께 실행한 성능은 아직 검증하지 않았습니다.

Babylon.js 장면 청크가 압축 전 약 952KB여서 Vite의 500KB 크기 경고가 있습니다.
3D 코드는 첫 화면 코드와 분리해 지연 로딩합니다. 실제 게임 에셋과 화면이 추가되면 로딩 시간과 메모리를 다시 측정합니다.

로그인·게임 저장·랭킹·실제 미션·운영 배포는 아직 구현하지 않았습니다.
CI는 같은 코드 검사와 개발 서버 기반 브라우저·DB 검사를 수행하며, 실행 결과는 GitHub Actions에서 확인합니다.

## SETUP-007 로컬 검증 — 2026-11-16

주민·건물의 식별값, 위치, 방향과 표시 상태를 공용 형식으로 정의했습니다. [전달 규격과 예제](SCENE_PROTOCOL.md)에 각 항목과 담당 경계를 설명합니다. Worker에서 React를 거쳐 Babylon 객체에 적용하며, API의 초기 상태 응답과 게임 저장 형식은 변경하지 않았습니다.

| 범위              | 결과                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| 로컬 실행 버전    | Node 26.13.1, pnpm 12.18.0 확인                                       |
| 의존성 설치       | `pnpm install --frozen-lockfile` 통과, lockfile 변경 없음             |
| 기본 검사         | `pnpm check` 통과: 코드·타입 검사, 단위 검사 13개, Core·API·Web 빌드  |
| 표시 정보 검사    | 일반 값 복사, 원본 보존, 중복 식별값·비정상 좌표 거부 확인            |
| Babylon 객체 검사 | 식별값으로 재사용, 위치·방향·색 갱신, 숨김·삭제·종료 정리 확인        |
| 실제 DB 연결      | `pnpm db:check` 통과                                                  |
| 실제 브라우저     | `pnpm test:e2e` 3개 통과, API·DB·Worker·3D 연결 및 브라우저 예외 없음 |
| 새 전달 예제      | 전환 후 캔버스 이미지 변경, 날짜 유지, 원상 복귀·새로고침 확인        |

초기 검사는 새 문서 표의 포맷과 테스트에서 사용할 수 없는 전역 타입 때문에 실패했습니다. 문서 포맷을 맞추고 코어에 브라우저·Node 전역 타입을 추가하지 않는 값 복사 검사로 보완한 후 위 검사를 통과했습니다. 과거 CI 성공과 이번 로컬 실행은 별도 근거입니다.

Node 공식 배포본의 SHA256을 확인하고 프로젝트 전용 실행 경로를 사용했습니다. 다른 프로젝트의 기본 Node 설정은 변경하지 않았습니다. 이번 검사는 Linux Chromium 소프트웨어 그래픽과 예제 상자 모델을 사용했습니다. 실제 공룡 모델·걷기 애니메이션·실제 GPU 성능은 검증 대상이 아닙니다. Vite의 장면 청크 약 953KB 경고는 남아 있습니다.

검사용으로 켠 로컬 PostgreSQL은 검사 후 중지했으며 데이터 볼륨은 보존했습니다. 운영 배포와 GitHub Actions의 새 실행은 수행하지 않았습니다.

| 범위             | 결과                                                                                        |

실제 디스크·브라우저 저장 공간을 가득 채우지 않았으며, 용량 부족 상황은 오류 주입으로 검증했습니다. 단위 검사는 메모리 저장소를 사용하고 브라우저 검사는 분리된 테스트 환경의 localStorage를 사용했습니다. 다중 탭 동시 저장, 다른 브라우저·기기 공유, 사이트 데이터 삭제 후 복구는 검증 범위가 아닙니다.

검사 후 로컬 DB는 중지하고 데이터 볼륨을 유지했습니다. 웹·API 검사 서버도 종료했습니다. 기존 Vite 장면 청크 크기 경고는 남아 있으며, 이번 변경의 커밋·푸시·운영 배포는 수행하지 않았습니다.

## 설정 메뉴·음량 검증 — 2026-11-16

| 메뉴 조작             | 키보드 음량 조절, Esc 닫기와 열기 버튼으로 초점 복귀                                                   |

첫 브라우저 검사에서는 13개가 통과하고 음량을 0%에서 100%로 바꾼 뒤 출력 노드 값이 0에 남는 검사 1개가 실패했습니다. 공용 음량을 예약 이벤트 대신 현재 출력값에 직접 적용하도록 수정했고, 해당 검사 1개와 최종 전체 검사를 각각 통과했습니다. 최초 실패와 후속 성공은 별도 근거로 보존합니다.

오디오 단위 검사는 가짜 장치를 사용하며, 브라우저 검사는 실제 AudioContext·GainNode의 연결과 출력값을 확인합니다. 실제 스피커의 청취 크기·음질을 측정하지 않았습니다. 저장 공간 부족과 오디오 사용 불가는 오류를 주입한 검사입니다.

React 변경은 저장소 읽기·오디오 생성 시점, effect 정리, 설정 변경의 이벤트 처리, 모달·레이블·키보드 조작을 검토했습니다. 기획 검토 문서 두 개는 변경하지 않았으며 커밋·푸시하지 않았습니다. 검사 후 로컬 DB를 중지하고 볼륨을 보존했으며 웹·API 검사 서버도 종료했습니다.

## 수동 BGM·음성 검증 — 2026-11-16

| 범위                  | 결과                                                                                             |

| 재생 연결             | 실제 HTMLAudioElement와 MediaElementAudioSourceNode로 WAV 재생, BGM 반복·음성 1회·동시 재생 확인 |

초기 기본 검사는 새 브라우저 테스트 파일의 포맷 불일치로 실패해 포맷을 맞춘 뒤 통과했습니다. 첫 전체 브라우저 검사는 16개 통과·1개 실패였으며, 실패 원인은 실제 35% 출력값 `0.349999994...`를 `0.35`와 완전히 같아야 한다고 비교한 검사였습니다. 소수 표현 오차를 허용하는 비교로 수정하고 해당 검사와 최종 전체 검사를 통과했습니다. 오디오 구현값을 바꿔 검사를 맞추지 않았으며 최초 실패 원본도 보존합니다.

음원은 테스트에서 생성한 PCM WAV이며 실제 BGM·대사 파일 내용이나 스피커 청취 품질 검증이 아닙니다. 단위 검사는 가짜 장치를, 브라우저 검사는 실제 오디오 요소·출력 노드를 사용합니다. 재생 권한 거부는 오류 주입이며 사건별 재생 조건·자동 전환·우선순위는 구현하지 않았습니다.

React의 공용 설정·오디오 소유권, 비동기 재생 응답 무시, 화면 종료와 파일 교체 정리를 검토했습니다. 기획 검토 문서 두 개는 변경하지 않았으며 커밋·푸시하지 않았습니다. 검사 후 DB를 중지하고 볼륨은 보존했으며 웹·API 검사 서버도 종료했습니다.
