## C1이 확인할 화면

첫 화면은 기존 겨울 섬·GLB 마을과 정찰 표시 시안을 유지한다. 하단 **건설(B)·주민(U)·연구(T)·조달(E)**에서 실제 생활 규칙을 계산하는 복홀 운영 장면으로 들어간다. 캔버스와 HUD는 유지하고 지형·표시 상태를 전환한다. 주민을 하나씩 선택하지 않고 건물·운영 인원·계약을 지정한다.

- 건설: 평탄한 빈 부지·자원 입지, 완성 모습 미리보기, 좌우 회전, 자재 확보 후 공사 대기열, 가까운 유휴 주민의 자동 작업.
- 생활: 실제 주민 60명, 개인별 허기와 식당 직원 배치, 식성별 배급·육식 대체, 고정 잠자리, 치료·퇴원.
- 생산·연구: 시설 단계, 자원 생산·운반·저장 상한, 야근 18~21시, 병원 단계, 공방과 후반 세 분기.
- 조달: 공급안 계약 후 운송·하역·전량 검수·복귀·공동 재고 반영. 건물 보수는 손상과 사용자의 직접 명령이 있을 때만 한다.
- 저장·개발 도구는 운영 장면을 닫지 않고 이용한다. 운영 장면을 닫을 때는 계산 Worker가 정지한 공동 재고·시각을 본 화면에 전달한다.

하단 건설·연구 버튼을 열었다고 자동으로 건물이 생기거나 연구가 시작되지는 않는다. 실제 자재·공방·인원·입지 조건을 충족해야 한다.

## 기존 조달 시연과 저장 보존

PR #10의 일손·불량품 교환·현장 선택 시연은 기존 4인·시간·검수·배분 규칙과 저장 형식을 보존한다. `legacy-timber.ts`와 `legacy-timber-scene.ts`는 이 시연의 호환 경계다. 기존 시연의 수동 배분이나 12시간 예시를 마을 생활의 자동 조달 규칙으로 적용하지 않는다. 일손 시연의 재고를 마을 공동 재고에 합산하지 않는다.

마을은 v17 저장과 v10~16 변환을 사용한다. 일손 시연은 기존 별도 저장을 사용한다. 서로 다른 저장을 강제로 변환하거나 원본을 지우지 않는다. 첫 화면의 정찰 표시 시안도 실제 마을 정찰 시설·인원·재고 정산과 구분한다.

## 그래픽과 조작 범위

PR #10의 원본 GLB·UI 이미지는 보존한다. 새 마을은 복홀 구릉·숲·광물·수역과 실제 시설 배치를 사용하며, 새 HUD의 건설·주민·연구 버튼을 연결한다. 모든 생산시설을 새 GLB로 교체한 최종 아트 통합은 아니다. 철광석·석재의 전용 아이콘이 없어 기존 철재·석탄 그림을 임시로 사용하며 이름과 수량은 각 자원으로 표시한다.

정책·온돌 전용 명령과 전체 캠페인 사건의 자동 발생, 구형 미연결 연구·스킬은 이 통합에서 새로 완성하지 않는다. 연구·의료 수치는 [연구·의료 규칙](RESEARCH_AND_MEDICAL_RULES.md), 건설 수치는 [건물 규칙](BUILDING_RULES.md)을 우선한다.

## 검증과 게시

PR #9의 모바일 화면 잘림은 작은 화면 캔버스 높이를 조정했다. 식당 연속 검사는 실제 건설·직원 이동·식사에 30초 이상 걸리므로 시나리오 전체 제한을 90초로 조정했다. 개별 동작의 기대 결과와 제한은 유지한다.

통합 과정의 화면 검사에서는 저장 배경막이 버튼을 가로막는 문제, 좁은 운영 패널의 다단 표시, 지연 로딩 삽화의 높이 누락을 수정했다. 검증 이력은 [개발 검증 기록](VERIFICATION.md)에 이어 기록한다. 실제 DB 연결과 원격 자동 검사는 로컬 화면 검사와 별개다.

커밋·푸시·새 PR 생성·브랜치 병합은 각각 C1의 승인 범위에 따라 진행한다.
